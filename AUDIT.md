## Decisions Made

**[Phase 0 correction]** Initial project-inventory extraction script over-counted 20 real projects as 22 by naively matching any `id:`-prefixed object in `projects.ts`, incorrectly including 2 entries from a separate `principalExperience` array. Corrected in place rather than silently fixed — retracted D2/D3(original)/D6, which were built on that false premise, and logged the retraction rather than deleting the trail.

**[Phase 1]** D1/D3(revised)/D4/D5 are **not patched in isolation** — `FloatingNavigationPanel`'s hardcoded Sector/Market lists are being fully replaced by Phase 3's data-derived menu, which structurally cannot offer a filter option with zero matching projects (the exact class of bug both defects are). Patching the doomed component now, then replacing it in Phase 3, would be the "half-applied refactor" pattern this brief explicitly warns about. Deferred, not skipped.

**[Phase 1]** Fixed the `generateMetadata` fallback title template in `projects/[slug]/page.tsx` (previously unconditionally appended "Design & Build" regardless of the project's actual services — currently unreachable since all 20 projects have `narrative.seo`, but a landmine for any future project added without one). Also fixed `openGraph`/`twitter` fields silently resolving to `undefined` when no `narrative.seo` exists, by computing `title`/`description` once and reusing them as the OG/Twitter fallback.

**[Phase 1]** No changes made to slugs/URLs — verified all 20 are already unique, kebab-case, and every `relatedProjects` cross-reference resolves to a real slug. No renaming needed, so no URL Change Log entries this phase.

**[Phase 1]** D7 (stale `dist/index.js`) logged but not fixed here — it has zero runtime impact today (`transpilePackages` routes around it) and touching the package's build output is more natural as part of Phase 6's dead-code cleanup, not a navigation/IA/SEO concern.

**[Phase 2]** Corrected the header-height math before implementing it. The original assumption (row height = logo height: 48px desktop / 36px mobile) was wrong — `MenuTrigger`'s own hit-area (originally 8px padding + 40px svg = 56px) was taller than the logo at every breakpoint, and since `.container` uses `align-items: center` with no fixed row height, the **tallest child**, not the logo, sets the row height. Verified empirically with Playwright (measured actual rendered header height = 80px against a target of 76-88px desktop / 56-64px mobile, not the 88px/60px the padding-only math predicted). Fix: reduced `MenuTrigger`'s padding (`--space-2`→`--space-1`, 56px→48px hit-area, still ≥44px touch-target floor), then recomputed padding against the corrected 48px row height — desktop `--space-4` (16px→80px total), scrolled `--space-2` (8px→64px), mobile `--space-2` (8px→64px, shared between resting/condensed since there's no further room to condense). Re-verified via Playwright after the fix: 64px at 320/360/375/768px, all within target ranges.

**[Phase 2]** Because header height changed, updated two dependent values that would otherwise have silently drifted: the global `--header-height` token (`apps/public-site/src/app/globals.css`, 112px→88px, plus a new `@media (max-width: 768px)` override at 60px — previously this token had no mobile variant at all, meaning mobile pages were already carrying a pre-existing ~12px over-clearance gap before this phase even started) and the hardcoded `112`/`80` literals inside `Header.tsx`'s own scroll handler that drive `--header-offset` for `ProjectFilterBar`'s sticky positioning (now computed per-breakpoint: 88/64 desktop, 60/60 mobile, matching the CSS exactly instead of guessing at it independently).

**[Phase 2]** Added one primary CTA ("Start Your Project," reusing the exact label already established on `about/why-ahw/page.tsx` and `getContactHubActions.ts` rather than inventing new copy) as a bordered pill in the header's control row, linking to `/contact`. Real-browser measurement at 320px showed the full-text pill (163px) plus the existing toggle/trigger group left zero margin and caused overflow. Rather than shrink the label into unreadable territory, added a `@media (max-width: 374px)` breakpoint that swaps the visible glyph to an arrow-only icon button (accessible name stays "Start Your Project" via `aria-label` on the anchor, which overrides visible content for the accessible-name computation) — consistent with the icon-only visual language `MenuTrigger`/`AppearanceToggle` already use at that size. Verified via Playwright screenshot at 320px: renders cleanly, no overflow, matches surrounding icon sizing.

**[Phase 2]** Expanded `AppearanceToggle`'s tappable area to the 44×44px floor via an absolutely-positioned invisible `::before` (`inset: -10px`), rather than resizing the visible 48×24px toggle track — preserves the existing visual design exactly (no "established design language" change) while meeting the touch-target requirement, since the pseudo-element is out of normal flow and doesn't affect the flex row's width/height calculations.

**[Phase 2]** Wired full keyboard/ARIA semantics onto the existing hamburger→full-panel pattern rather than rebuilding it as a traditional desktop mega-menu (see D5): `MenuTrigger` now forwards a ref and sets `aria-haspopup="dialog"` + `aria-controls` pointing at the panel; `FloatingNavigationPanel` got `id`, `role="dialog"`, `aria-modal="true"`, `aria-label`; `Header.tsx` adds Escape-to-close-with-focus-return, body scroll lock (`overflow: clip`, not `hidden` — reusing the exact lesson from the earlier Hero-regression fix this session, where `hidden` on one axis silently coerces the other axis to `auto` and creates an unintended scroll container that can hijack `position: sticky` descendants once the lock lifts), and an `onBlur`-based close when focus leaves the trigger+panel group entirely. Interpreted "preserve established design language" as protecting the *visual* interaction pattern (full-panel reveal, not a hover dropdown), not as an excuse to skip the phase's ARIA/keyboard targets, which are mechanism-agnostic. All four behaviors (Escape+focus-return, outside-click-close, scroll-lock toggling, dialog semantics) verified functionally via Playwright against the running dev server, not just read from source.

**[Phase 2]** Fixed a real keyboard trap-adjacent bug found while implementing the above: `FloatingNavigationPanel`'s Sector/Market/subitem accordions only opened on `.primaryBlock:hover`, so Tab-only users could focus a sub-link sitting inside a `grid-template-rows: 0fr; overflow: hidden` wrapper — technically focusable, invisible in practice. Fixed by adding `:focus-within` alongside `:hover` on the two accordion-trigger rules. Logged as D9 (see Defect List) since it's a genuine, independently-discovered accessibility defect, not merely an implementation detail of the CTA work.

**[Phase 2]** Normalized the header's motion timing to the phase's explicit 150-250ms / `cubic-bezier(0.4,0,0.2,1)` target (previously 500-600ms using a different curve, `cubic-bezier(0.16,1,0.3,1)`) and added a single consolidated `prefers-reduced-motion: reduce` block at the bottom of `Header.module.css` covering every transition declared in that file (including the currently-unused `.megaMenu`/`.megaPreviewImage` rules — see below), plus matching guards added to `MenuTrigger.module.css`, `AppearanceToggle.module.css`, and `FloatingNavigationPanel.module.css`. No existing token matched the 150-250ms target (closest is `--transition-fast` at 300ms), so the literal value is written directly in the header stylesheet rather than added as a new global design token, since it's a one-off, phase-specific spec rather than a reusable pattern.
